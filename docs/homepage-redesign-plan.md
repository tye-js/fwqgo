# fwqgo 首页重构落地方案

日期：2026-10-06。实施更新：2026-10-07。状态：中英文首页重构已实现；用户选择保留现有多个推广位。实现与验证记录见第 10 节。

## 1. 已确定的决策

| 项目 | 决策 |
| --- | --- |
| 首页目标 | 先阅读优惠和测评文章，形成判断，再进入套餐或商家页面 |
| 主要问题 | 找文章、找优惠不方便 |
| 主要读者 | 有购买需求、懂一些基础、需要内容辅助判断的用户 |
| 兼顾读者 | 已了解商家、地区、线路，希望快速找到内容的有经验用户 |
| 主要找法 | 浏览最新内容 |
| 辅助找法 | 按地区和线路找相关文章 |
| 文章展示 | 小图文列表 |

由此确定首页的主要路径：最新文章 / 地区线路入口 → 文章或文章集合 → 已有的套餐与购买承接。

以下属于本方案的建议默认值：延续现有蓝色与浅底视觉、首批展示 9 篇、推广以外的辅助模块合并精简。它们是实施基线，不是用户逐项确认过的要求。

## 2. 实施范围

- 第一阶段覆盖中文 `/` 与英文 `/en` 首页，共用展示组件，分别加载对应语言的内容。
- 调整首页的信息顺序、搜索区样式、文章展示、文章主题入口和辅助区域。
- 复用现有公开前台技术栈、分类/标签页、搜索、图片管线及 CMS 运营位。
- 不重设计 CMS、文章详情、全站导航或服务器库存页；不修改数据库结构，不新增自动内容归类或 AI 调用。
- 如需扩展共享文章组件，只新增首页使用的变体，保留其他页面的视觉和交互。
- 实施前复查工作区。当前存在未提交的文章 SEO 修改；本方案不接管或覆盖它们。

## 3. 页面结构

### 桌面（从现有 xl 断点开始）

```text
现有全站导航
──────────────────────────────────────────────────
首页标题与一句说明              紧凑搜索框 + 搜索按钮
地区文章入口：最多 4 个    线路文章入口：最多 3 个
──────────────────────────────────────────────────
最新文章                        站长推荐（最多 3 篇）
┌ 小封面 ┐ 标题                 工具与知识入口
└────────┘ 简短摘要 / 日期 / 标签  查看服务器套餐
          ……连续 9 篇……        推广（保留现有多个）
继续浏览全部文章
──────────────────────────────────────────────────
现有页脚
```

### 手机和平板（低于 xl）

```text
现有移动导航
首页标题与一句说明
搜索框 + 搜索按钮
地区入口、线路入口（换行展示）
最新文章：9 篇统一的小图文条目
继续浏览全部文章
站长推荐 → 工具与知识 → 套餐入口 → 推广
现有页脚
```

主列表在手机上保持连续，地区/线路入口位于列表之前，不再藏在长列表后的侧栏。辅助内容靠后属于本次选择“最新内容为主”后的有意安排。

### 现有模块如何处理

| 现有模块 | 建议处理 | 目的 |
| --- | --- | --- |
| 首屏介绍、搜索 | 保留并压缩上下留白 | 更早露出文章 |
| 1 篇大头条 + 2 篇次级 + 6 篇列表 | 合并为 9 篇等权小图文列表 | 连续扫读，不把最新一篇默认当作精选 |
| 热门服务器入口 | 改为地区、线路的文章集合入口 | 与“先阅读”目标一致 |
| 库存总数、局部套餐更新时间 | 从首屏移除，保留一处套餐库入口 | 减少与文章竞争的内容，也避免把局部更新时间当全库实时性 |
| 优惠码速览 | 第一阶段从首页移除，文章里的优惠内容保留 | 优惠码需要活动条件配套解释，首页聚焦文章发现 |
| 站长推荐 | 最多 3 篇，与主列表去重 | 提供辅助阅读，控制密度 |
| 工具、知识卡、下单提醒 | 合并成一组紧凑的“选购工具与知识”入口 | 保留帮助读者判断的能力 |
| 底部地区/商家库存目录 | 从首页移除，沿用库存页承接 | 避免与顶部文章主题入口混淆 |
| 多处推广模块 | 按第 6 节的既有数量上限重排 | 明确推广身份，不改变最新文章排序 |

这里的移除均指首页展示；不删除已有内容、CMS 配置或其他页面功能。

## 4. 模块与交互规则

### 4.1 最新文章

- 使用已发布且符合现有公开内容条件的文章，按 `createdAt DESC, id DESC`，首批 9 篇。
- 模块名称使用“最新文章 / Latest articles”。当前没有独立的可靠发布时间字段；沿用创建时间口径，并在实施前核对是否存在“旧草稿刚发布”的业务需求。旧文普通编辑不会因此置顶。
- 不采用自动轮播、无限滚动、默认大头条或按浏览量混排。
- 标题与图片指向同一文章；沿用现有 `PublicLink` 的链接行为。标签是独立链接，不嵌套在文章链接内部。
- 列表结尾保留进入现有全部文章第 1 页的入口。链接写“浏览全部文章”，不承诺从首页第 10 篇接续，避免与现有归档分页形成错误契约。
- 主列表不重复文章；站长推荐与主列表按文章 ID 去重，不为补足数量加载无关内容。

### 4.2 单个小图文条目

| 元素 | 规则 |
| --- | --- |
| 封面 | 左图右文；桌面建议 144 × 90px；低于 640px 建议 80 × 60px；保持固定容器比例并裁切，不拉伸原图 |
| 标题 | 首要视觉信息，完整换行，不省略价格、配置、线路等可能出现在标题里的内容 |
| 摘要 | 使用已保存描述，最多两行；描述缺失时省略，避免大量相同占位句；不即时调用 AI |
| 日期 | 使用现有时间格式与显示时区，日期无效时省略 |
| 标签 | 最多 3 个已有标签，名称按语言解析；不凭标题推断地区、线路或“测评”身份 |
| 标签链接 | 只有满足既有公开条件、具有有效 slug 的标签才可点击；其余展示文本 |
| 商家、价格、折扣、有效性 | 不新增独立徽章，除非已有可靠的结构化绑定；不从摘要抓取后冒充实时事实 |
| 操作 | 标题与图片提供文章入口，不给每行增加抢眼的大按钮；所有实际可点击区域至少 44px 高 |

标题与标签都允许换行；只限制描述摘要。条目高度随内容增长，禁止用固定高度掩盖长标题问题。图片顶对齐，标签必要时放到整行底部。图片在 320px 宽度下仍需给文字留下足够空间，验收时必要可将窄屏封面缩至 64px。新变体必须提供独立的 `sizes`，匹配最终 80 / 144px（或经验证调整后的）图片宽度，不能落入旧列表 232px 的默认分支。

标签数是上限而非必须凑齐的数量。现有标签来源没有可靠的主次属性顺序，不将第一个标签标为“主要线路”或“主要地区”；缺少合格标签时允许不展示。

### 4.3 地区、线路文章入口

- 地区最多 4 项、线路最多 3 项；手机直接换行，不依赖横向滑动才能发现内容。
- 地区优先复用现有文章分类，线路优先复用标签。进入文章集合，不把同名快捷入口直接送入 `/servers/*`。
- 路径由实际实体与规范 slug 生成，不能按显示名称拼造：中文分类 `/fwq/{slug}/page/1`、标签 `/fwq/tags/{slug}/page/1`，英文使用对应 `/en` 路径与语言身份。
- 实施前只读核对候选分类/标签及对应语言的合格文章量。中国香港、美国、日本、CN2 GIA、CMI 等只是候选，不是已经核实的固定清单。
- 沿用现有公开策略作为首页推荐门槛：分类至少 3 篇；标签还需 `indexable=true`。这属于首页入口筛选，不意味着所有低于该门槛的现有页面都会 404。
- 中文与英文分别筛选；没有合格内容的入口不显示，不补一个错误语言或空白目标。不能仅根据最新 9 / 12 篇推断全站主题文章量。
- 用服务端固定优先顺序加资格过滤，第一阶段不新增 CMS 编排器。标签表没有可靠的“地区 / 线路”类型字段，因此先维护少量带类型的候选身份清单，再精确读取实体校验；不从模糊匹配或标签名猜出“热门线路前 3”。只为少量实际需要的主题读取必要字段，避免逐条重复回查；允许增加首页专用的只读查询。
- 地区枚举采用“中国香港 / Hong Kong, China”“中国台湾 / Taiwan, China”；此规则不要求改写“香港服务器”等位置描述。新枚举文件纳入现有地区合规检查。
- 当前没有已核实的“更多地区/线路文章”目录页；首期不制作一个无目标的“更多主题”按钮。全部文章和搜索可承接剩余需求。

### 4.4 搜索与辅助入口

- 搜索文案聚焦文章，例如“搜索商家、地区、线路或文章”。桌面与简介并列，小屏独占一行；输入框和按钮高度至少 44px。
- 第一阶段保留中文标签匹配成功后进入标签页、失败后进入 `/search` 的现有逻辑；英文沿用 `/search?lang=en`。不把首页本地 9 篇过滤伪装成全站搜索。
- 保留空输入提示、提交状态与失败后的正常搜索降级；本期不新增高级筛选器、搜索建议服务或搜索排序算法。
- “站长推荐”继续来自现有推荐分类；它并不是新增的人工头条排序。去重后不足 3 篇就少显示，没有则隐藏。
- “选购工具与知识”保留知识库、服务器配置、网络线路工具三个入口，使用现有中英文路径。
- 套餐库只保留一处清晰入口。现有英文库存树不完整，英文首页不得制造 `/en/servers` 路径；沿用既有目的地，并明确其语言，完整英文化另立项目。

## 5. 视觉与响应式基线

- 延续目前公开前台的浅蓝灰背景、白色内容面、蓝色链接，以及现有深色模式，不另引入字体或 UI 框架。
- 复用 1248px 公共容器和 16–32px 自适应边距。xl 起保持约 300px 辅助栏，主栏单列；低于 xl 单列阅读。
- 小图文列表用细分隔线或轻边框区分条目，弱化大圆角、厚阴影和整行抬升动效。样式只针对首页变体。
- 标题建议桌面 18px、手机 16–18px；摘要 14px；元信息 12–13px。标题和正文保持易读对比度。
- 首屏目标：在 1440×900 和 375×812 的代表性中英文内容下，能看到第一篇标题；以真实渲染验收为准，不靠截断或遮挡实现。
- 保留键盘焦点、清晰标签、44px 触控尺寸、安全区和减少动画支持；不得用页面级隐藏横向溢出来“修复”布局。
- 改造首页卡片图片 `sizes` 时要与最终 CSS 尺寸一起调整，并继续通过已有图片优化器。只对实际首屏优先图片设置优先加载，不能给 9 张都加优先级。

## 6. 商业推广：保留现有多个推广位

用户在实施会话中已选择“保留现有多个推广位”。不执行原建议中的最多 2 条收敛方案，也不合并或写回 CMS 配置。

| 原运营位 | 新首页位置 | 沿用的展示上限 |
| --- | --- | --- |
| `hero_primary` | 桌面辅助栏工具区之后；手机在主列表与阅读辅助内容之后 | 首个有效条目 1 个 |
| `sidebar` | 主推广之后的独立推广区 | 最多 6 个；沿用原有推广文章后备列表最多 3 篇 |
| `promo_grid` | 双栏主体之后的推广网格；手机位于全部阅读辅助内容之后 | 最多 6 个 |
| `featured_offers` | 不恢复首页展示 | 0 |

沿用现有启用、语言、有效期、内容可用性和位内排序规则。没有有效记录就隐藏，不留空槽。全部商业推广区域明确标注“推广 / Sponsored”，主推广卡也直接显示该标识；推广标题完整换行，与编辑推荐区分。

## 8. 实施顺序与交付

1. **主题与内容核对**：只读确认中英文候选入口、文章量、slug、发布时间口径、推荐去重结果和推广映射。产出可用入口表，不修改内容。
2. **首页与条目实现**：完成 `home-list`、首页布局、搜索样式和手机单列；中英文同步。先用长短标题、有无图片、有无摘要的样本检查。
3. **数据接线与收尾**：接入真实主题资格与推荐；按确定的推广选项处理；清理不需要的首页取数，保持首个 HTML 有内容。
4. **验收**：完成下面的功能、视口与工程验证，交付代码差异与验证结果。部署不包含在当前方案请求中；以后收到“部署”指令时，遵守仓库的验证、提交并推送流程。

不预先承诺工期：先核对现有数据质量与推广选择，再给出估时。首期不附带全站重设计、英文库存建设或新的后台编排能力。

## 9. 验收标准

### 内容发现与操作

- 最新流保留确定的排序，最多 9 篇，不重复；没有超大自动头条。
- 读者从首页点击一个可见地区/线路入口即可进入对应语言的文章集合；链接无 404，标题与目标含义相符。
- 搜索能够提交真实全站查询，保留标签匹配、错误提示和失败降级；不是只过滤首页当前列表。
- 文章标题完整可读，缺失摘要/标签不产生大块空白；标签不会遮挡标题或改变文章链接。
- 主列表和站长推荐去重；推广若保留，身份和位置符合最终选择。
- 图片缺失、主题不足、推荐不足、英文内容较少、真实空列表与数据查询失败分别按规则处理。

### 响应式、性能与 SEO

- 在 320、375、768、1024、1440px 下验证中英文及长标题样本；无页面横向溢出，按钮和可点击标签至少 44px 高。
- 真实浏览器检查键盘、焦点、搜索提交、分类跳转和现有导航关闭行为；深浅色均可读。现有 `smoke:mobile` 的首页视口循环只覆盖 `/`，实施时补上 `/en`，不能直接把旧脚本通过解释为双语已验证。
- 图片 `sizes` 与实际槽位一致，走优化器，保留明确宽高比；不把全部图片提升为首屏优先。
- 首页首个 HTML 包含标题、文章标题和链接、描述等主体信息；保留 canonical、hreflang、结构化数据以及 RSC 缓存边界。
- 不降低其他公开文章列表、文章详情及 CMS 的既有行为；共享变体回归检查同时覆盖。
