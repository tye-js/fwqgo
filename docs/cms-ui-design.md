# FWQGO 后台界面设计

方向：清爽、专业的内容管理工作空间。通过清晰的导航、稳定的操作位置和适合长时间编辑的布局，组织已有的内容、任务、知识、套餐与媒体功能。

## 视觉规范

| 项目     | 规范                                                                                      |
| -------- | ----------------------------------------------------------------------------------------- |
| 配色     | 浅灰蓝背景、白色面板，蓝色 `hsl(219 80% 47%)` 用于主操作和选中状态；提供配套深色变量      |
| 页面     | 内容最大宽度 1600px，16–32px 响应式边距；标题、说明、操作栏与内容区分层                   |
| 面板     | 14px 圆角、细边框和轻阴影，统一指标卡、筛选工作区、表格和表单                             |
| 导航     | 桌面侧栏宽 248px，折叠为 64px 图标栏；低于 1024px 使用抽屉                                |
| 编辑器   | 正文占主要宽度，桌面右侧设置栏为 350px / 380px；较小视口纵向排列                          |
| 可访问性 | 主要控件至少 44px，保留焦点轮廓、跳转工作区链接、语义标题和表单错误关联；响应减少动画设置 |
| 隔离     | `src/styles/cms.css` 仅由 CMS 根布局导入，限定在 `html.cms-app` 下；不改公开前台配色      |

## 页面与操作

| 区域       | 设计与行为                                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------------------------- |
| 侧栏       | 工作台、内容管理、任务中心、知识管理、服务器套餐、图片媒体、内容运营、接口设置；草稿、SEO 子页和图片入口分别呈现 |
| 顶部栏     | 当前页面路径、页面搜索、查看网站、新建文章；`⌘ / Ctrl K` 打开页面搜索                                            |
| 页面搜索   | 搜索已有导航名称及分区；Enter 打开首项，↓ 进入结果，Tab 切换，Esc 关闭；使用真实链接以保留未保存离开保护         |
| 运营工作台 | 采集、编辑、质检和首页运营四条入口；关键指标、内容趋势、待处理事项与最近文章均读取已有后台统计                   |
| 文章编辑   | 优先展示完整正文；保留复制、英文生成、封面生成、SEO 与发布设置；来源、双语关系和内链管理可展开查看               |
| 列表与任务 | 统一搜索、筛选、批量操作、选中数量和空状态；宽表由自己的滚动容器承接，手机继续使用卡片展示                       |
| 图片资产   | 加大缩略图，文件名与 URL 允许换行；保留引用检查、替换、上传和删除操作                                            |
| 登录与注册 | 共用品牌与功能说明布局；保留密码显隐、账号自动填充、错误反馈、提交禁用和既有注册开关                             |

## 兼容范围

- 本轮修改 CMS 展示与导航，不调整数据库、鉴权接口、文章收集、保存与发布规则。
- 正文复制、中文文章生成英文、按描述手动生成封面和未保存离开保护仍保留。
- 导航使用最长路径匹配，避免知识条目与来源资料、主页 SEO 与标签 SEO 同时选中。
- 折叠侧栏中的图标保留可访问名称；内容区域可纵向滚动，避免小高度窗口裁掉下方入口。
- 不通过页面级隐藏横向溢出来掩盖布局问题；表格继续使用 `TableViewport` 及服务端输出的移动标签。
- 没有新增依赖，也没有修改公开前台、生产配置或部署流程。

## 验证记录

- 使用项目固定的 Bun 1.4.2。完整 `bun run check` 通过，包括 lint、类型检查、520 项已有本地测试和文章工作流、安全、依赖、缓存等检查。
- 新增 `verify:cms-ui` 并接入 `check`。5 项回归覆盖导航目标有效性、最长路径匹配、搜索、真实侧栏组件的服务端渲染与登录表单语义；折叠导航收尾后再次通过相关检查、lint 和类型检查。
- CMS 移动结构检查通过：33 个页面、29 组响应式表格、27 个原生表格单元格的移动标签；这些是结构检查，不代表真实视口验收。
- Web / CMS 双应用构建与 `smoke:built` 通过。独立运行包的原生图片处理、健康接口、登录跳转、鉴权边界和路由隔离通过检查；依赖真实生产内容的检查没有启用。
- 本地 HTTP 检查确认登录页返回完整表单及新版样式，CMS 样式已随静态资源正常提供，公开前台构建中未混入 CMS 主题。
- 已计算浅色与深色的正文、辅助文字、主按钮、侧栏选中态和错误提示颜色对比度，上述组合均达到 WCAG AA；最低为浅色辅助文字 5.50:1。
- 已执行 `bun run smoke:mobile`，Chromium 在启动阶段返回 `Code: null`，测试中止。真实视口、点击、键盘操作与视觉截图仍未验收，没有将静态或服务端渲染检查当作浏览器验证。
- 验证使用本地隔离数据库地址并关闭后台任务，没有操作生产数据或真实 AI 服务。本轮未提交、推送或部署。

## 浏览器可用后的验收重点

1. 在 320、390、768、1024、1280px 宽度检查登录页、文章列表、编辑器、任务列表和图片资产的溢出、换行与触控区域。
2. 检查抽屉跳转后关闭、折叠侧栏分组展开、页面搜索键盘导航与对话框焦点恢复。
3. 在有未保存正文的文章中，通过侧栏、页面搜索和新建文章入口离开，确认仍出现原有离开提醒。
4. 使用可控测试文章检查复制未保存正文、保存反馈、双语入口和手动封面任务状态。
