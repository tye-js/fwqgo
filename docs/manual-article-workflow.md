# 文章采集与草稿编辑

文章生产流程收敛为：**读取素材 → 清洗正文 → 替换返利链接 → 保存草稿**。

## 采集与保存

- URL、文本、邮件和文本文件共用同一入稿流程，不调用正文改写、翻译或文章 SEO 模型，也不要求可用的文本模型配置。
- 清洗后的完整来源快照单独保存。返利链接替换后的正文作为 Markdown 保存到草稿，表格中的各套餐购买链接完整保留，不按历史 AI token 限制截断。
- 每篇文章只读取一次返利商家配置。参数模式只替换指定参数；`affParam=href` 仍替换成数据库配置的整条地址。
- 使用来源标题和已有摘要作为初值，草稿 slug 带任务 ID 以区分不同采集任务；关键词、标签及最终 SEO 由编辑补充。缺少摘要或标签不会阻止保存草稿。
- 草稿、任务完成状态、素材完成状态和保存步骤在同一事务中提交，并核对任务租约。保存失败会回滚；重复执行不覆盖已经编辑或发布的文章。
- 新采集任务直接到 `succeeded`，不再停在 `manual_required`。旧的待人工处理任务可点击重试，优先使用完整来源快照入稿，无需重新访问已下线的来源。

## 编辑与复制

草稿箱进入文章编辑页后，在正文工具栏点击“复制全文”，复制的是编辑框内的全部 Markdown，包括尚未保存的修改、表格、列表和链接。剪贴板不可用时会选中全文并提示手动复制，不会误报成功。

正文和 SEO 统一在草稿中编辑。保存未发布草稿允许摘要与标签尚未完成；从正文编辑页发布时继续校验正文、摘要和标签。

## 英文翻译

中文文章编辑页点击“生成英文文章”，后台使用已启用的文本模型配置翻译已保存的完整中文正文，并生成对应的英文标题、摘要和标签，原子保存为独立的未发布英文草稿。中文有未保存修改时，按钮提示先保存；文章列表也保留批量英文生成入口。

翻译保留每个表格行和购买链接，不按 Max Tokens 数值截掉中文输入。输出仍未完成或链接、表格结构校验失败时，不保存残稿。正文与元信息各自保存完成记录，保存失败或后续步骤失败后重试可复用结果。中文内容在生成期间更新时拒绝写入旧译文，任务记录保留生成结果，需从中文文章页重新发起翻译。

已有英文文章保留并提供编辑入口，不覆盖中文原文或已有译文。英文正文和 SEO 可在英文草稿中继续编辑；独立 SEO 队列保持停用。历史未标记为主动翻译的英文任务继续保留人工输入表单与重试，不会因升级自动调用模型。

## 封面与历史兼容

新草稿立即使用 `/img/placeholders/fwq-placeholder.png`。中英文文章页均提供“生成封面图”，点击后读取当前编辑框的文章描述，结合对应语言的 AI 生图提示词、模型、尺寸和质量配置创建后台任务。缺少描述时提示补充，不提交请求；批量生成会跳过缺少描述的文章并说明数量。

保存文章不查询图片配置、不创建生图任务。生成成功后替换请求时的封面，保护生成期间手工换过的图片；失败则保留当前封面。旧任务没有描述快照时，可从文章当前描述补充后重试。标题用于辅助上下文，正文、关键词及旧视觉简报覆盖值不再作为文章封面输入。

中文采集的人工入稿等待表单、独立 SEO 派生任务、重复生产链路、模型 token 面板及 AI 质量规划步骤已退出采集流程。英文版本保留派生任务和历史人工表单，只有主动请求并带翻译标记的新任务调用模型。任务表字段和历史模型调用记录保持可读，任务详情展示翻译进度和历史记录。不删除生产数据，也不需要数据库迁移。

## 验证

```sh
bun run verify:article-workflow
bun run verify:ai-rewrite-prompts
bun run verify:article-seo-links
bun run verify:security-runtime
bun run lint
bun run typecheck
SKIP_ENV_VALIDATION=1 bun run build
bun run smoke:mobile
```

本地无生产配置的构建使用 `SKIP_ENV_VALIDATION=1`，正式发布继续由 GitHub Actions 使用完整生产环境构建。验证结果必须分别说明代码检查、运行时测试和真实浏览器/剪贴板是否完成。
