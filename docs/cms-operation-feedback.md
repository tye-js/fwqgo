# 后台操作状态反馈

## 交互顺序

1. 点击重试或确认操作后，立即显示提交态，替换该任务的旧失败提示，并锁定同一任务的操作按钮。
2. 请求被服务端接受后，重试显示“已加入队列”；取消、删除和标记完成分别显示已确认的结果。页面同步期间继续保持操作锁。
3. 服务端页面更新完成后，使用返回的真实状态与筛选结果。任务可以已开始运行、已经结束，或从当前筛选列表移除。
4. 请求失败或连接中断时，恢复原有展示并给出可读提示，允许再次操作。

供应商采集的每次运行独立保存，重试会安排新运行。因此提交后显示“已提交新运行”，历史失败记录保留原状态，新进度从新运行记录查看。

## 实现范围

- 任务中心列表和文章、封面、供应商采集详情共用 `TaskMutationBoundary`，同步状态标签、进度、说明与错误提示。
- `useAdminMutation` 同时追踪请求阶段和刷新阶段，按业务键阻止重复提交。不同任务可以独立操作。
- 已有供应商、套餐、知识库等使用通用 mutation hook 的页面也会保持等待状态直到相关刷新完成。
- 重试、恢复、取消、删除和标记完成使用相同反馈顺序。删除确认和不确定生图请求的人工确认仍保留。
- 有活动任务的页面自动刷新；上一轮刷新未完成时暂停计时器，隐藏页面不发送轮询请求。
- 服务端鉴权、任务状态校验、队列和任务执行规则没有调整。

`bun run verify:cms-mutations` 使用真实 React DOM 与 Happy DOM，模拟延迟的请求和页面刷新，已接入 `verify:cms-ui` 和完整 `check`。

8 组交互回归覆盖即时状态、重复点击、刷新期间的锁、错误恢复、快速结束状态、筛选后的任务移除、确认弹窗、多任务并行及轮询节流；任务行的移动标签同时检查服务端 HTML 和客户端 DOM。

Happy DOM 仅作为开发测试依赖。模拟 DOM 测试不代表真实浏览器或视口验收，后者仍需在可启动 Chromium 的环境执行 `bun run smoke:mobile`。
